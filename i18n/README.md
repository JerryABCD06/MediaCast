# 翻译

## 怎么说清楚这个项目里的语言

**源语言是中文。** 也就是说代码里 `tr("播放")`、`qsTr("播放")` 写的就是最终
要显示的中文，`.ts` 文件只负责把它换成别的语言。这么做有两个原因：

1. 这个软件本来就是中文优先的，界面文字每改一次都是一次回归风险。源语言
   直接用中文，等于"不装翻译器时的样子"和现在**一字不差**。
2. 旧界面（Widgets 那套）还没接翻译，文字仍然是硬编码的中文。要是新界面
   改成英文源语言，同一个程序里就会一半中文一半英文。

所以：**中文环境下即使一个 `.qm` 都没有，界面也完全正常。** 这不是巧合，
是上面这条决定的直接结果。

## 哪些字符串该进翻译，哪些不该

规矩只有一条：

> **会出现在界面上的文字走 `tr()` / `qsTr()`；纯调试日志不动。**

日志是个诊断通道，DLNA、播放器、界面都往里写。只翻译其中一部分，得到的
是"一半英文一半中文"的日志流，查问题的时候更难看。真要翻译日志，那就整条
通道一起翻，那是另一件事。

例外：**语言名不翻。** `MainWindow` 里的"中文""English"故意没套 `qsTr()` ——
语言名就该写成它自己的语言，翻成 "Chinese" 反而让不懂英文的人认不出来。

## 加一种语言

1. 在 `CMakeLists.txt` 的 `qt_add_translations` 里，往 `TS_FILES` 加一行
   `i18n/MCast_<语言>.ts`
2. 在 Qt Creator 的构建菜单里跑 `update_translations`（它调用 lupdate），
   新文件会被生成出来
3. 用 Qt Linguist 或者直接编辑那个 `.ts`，把 `<translation>` 填上
4. 重新构建 —— `lrelease` 会把 `.qm` 编出来并塞进 exe 的资源

运行时 `UiState` 会按系统语言自动挑对应的 `.qm` 装上，代码不用改。

## 加了一个 QML 文件之后

**必须**把它加进 `CMakeLists.txt` 里 `qt_add_translations` 的 `SOURCES`。
我们的 QML 是塞在普通 `.qrc` 里的，不是 `qt_add_qml_module` 建的模块，
lupdate 自己发现不了它们。漏了的话，那个文件里的字符串永远收不进 `.ts`，
界面上那部分就一直是中文。

## 文件所有权

`MCast_en_US.ts` 是 **lupdate 生成的**，但里面填的译文是**人写的**。

- 跑 lupdate 只会补新条目、不会覆盖已填的译文
- 但它会**重写整个文件**，所以写在这个 `.ts` 里的注释保不住 —— 说明性文字
  都放这份 README 里
- 删掉不再用的条目用 `lupdate -no-obsolete`，否则废弃条目会一直留在文件里
