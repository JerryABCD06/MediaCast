# 生命周期与关闭

日期：2026-11-14

基线：`6c990a3`

## 1. 关闭入口

主窗口关闭只有一组用户入口：

```text
系统关闭按钮 / Alt+F4
  -> Avalonia Window.OnClosing
```

若 `peerConnected=true`，显示关闭策略：

```text
Pause and close
End cast and close
Cancel
```

`peerConnected` 仍只来自 Protocol 投影。关闭对话框不创建 UI 本地连接状态。

## 2. 正常关闭顺序

用户确认关闭后：

```text
停止接受新的关窗决定
  -> PauseAndFlushForWindowClose
       -> PlaybackController.pause
       -> 直接提交最终 PlaybackStateDelta
       -> 封住 PlaybackBridge，停止其 reader/writer
  -> 窗口关闭
  -> Avalonia GL surface deinit
       -> RenderDetach
  -> desktop.Exit
  -> native host destroy
       -> 停止 reconnect worker
       -> 停止 Playback/Control producers
       -> 取消 playback refresh timer
       -> EventLoop barrier
       -> 断开 controller/player connections
       -> 停止 SMTC
       -> 清 update callback，释放 render context
       -> 停止 MPV event thread，销毁 mpv handle
       -> 停止 EventLoop，销毁 HostState
```

关键约束：

- pause 状态必须尽力在 PlaybackPipe 仍可用时提交；
- 提交完成后立即封住后续播放发布；
- GL surface 销毁不能被解释成新的媒体失败并覆盖最后一次 pause；
- 任何 EventLoop 已排队任务必须在 MPV/SMTC 析构前排空；
- native callback 在 C# `GCHandle` 释放前清除；
- 用户关窗最多等待有限时间，连接失败仍必须退出，不能无限挂起。

## 3. EventLoop barrier

native host 在停止 producer 后向 EventLoop 投递空 barrier：

```text
post(barrier)
wait up to 10 seconds
```

barrier 返回证明此前排队的播放、投影、timer 任务已经执行完。

若 barrier 超时：

```text
记录 "Avalonia shutdown barrier did not complete"
先 stop/join EventLoop
再析构 MPV/SMTC/render context
```

选择先停 EventLoop 是为了避免在旧任务仍可访问 HostState 时并发销毁其成员。
该超时路径仍需故障注入覆盖；它不会用 `detach` 或 detach thread 伪造有界成功。

## 4. PlaybackBridge 封口

`PauseAndFlushForWindowClose` 现在执行：

```text
HostState.closing = true
pauseAndFlushState()
playbackBridge.stop()
```

关闭后：

- 新 PlaybackBridge attach 被拒绝；
- `PlaybackUiReady` 不再发送；
- Surface detach 引起的 MPV `video output initialization failed` 只存在于
  即将退出的 UI 本地，不再作为新的 state delta 发往 Protocol；
- ControlPipe 仍由 Shell 生命周期拥有，直到宿主销毁。

## 5. fail-closed 关闭

ControlPipe 丢失、renderer context lost、Shell fatal reason 或 UI session
不连通时，App 调用 `CloseForHostShutdown`，跳过用户关闭策略，直接进入宿主销毁。

该路径不伪装为“用户正常关闭”，也不向播放协议补发正常 pause 成功。

## 6. 代次与所有权

| 资源 | 关闭时所有者 | 处理 |
|---|---|---|
| Avalonia Window | UI | 先停止输入 |
| GL surface | Avalonia | deinit/lost 进入受控 ABI |
| `mpv_render_context` | native host | 清 callback 后释放 |
| MPV event thread | `MpvCore` | join 后 terminate/destroy |
| Playback reader/writer | `PlaybackBridge` | stop 后 join |
| Control reader | `UiConfirmationBridge` | stop 后 join |
| SMTC | `WindowsMediaControls` | detach |
| reconnect worker | native host | stop 后 join |
| projection callbacks | native host | destroy 开始即清空 |

没有新增第二个播放器、第二个 renderer 或 C# 播放状态。

## 7. 真实验收

使用 lavfi 60 fps 视频完成真实三进程投送，然后在播放中点击系统关闭按钮，
选择 `Pause and close`。

日志顺序：

```text
Playback: 传输状态 -> PAUSED
UI intent: PauseAndFlushForWindowClose
Window close: pause and state flush completed
Render context detached
Avalonia UI exiting
Avalonia shutdown: producers stopped
Avalonia shutdown: event loop drained
Avalonia shutdown: render context released
Avalonia shutdown: MPV event thread stopped
Avalonia native host stopped
```

验收结果：

- UI 窗口和进程退出；
- PauseAndFlush 在 3 秒上限内完成；
- EventLoop barrier 在有限时间内排空；
- GL detach 后 UI 内出现 MPV video-output 关闭错误，但 PlaybackBridge 已封口，
  不再向 Protocol 发布新的 Stopped/loadFailed；
- Protocol 日志没有收到由 GL detach 导致的额外 `STOPPED` 状态；
- 旧测试实例未被终止。

## 8. 剩余验收

- 确认框打开时再次点击关闭；
- pause flush 写入超时；
- EventLoop 有积压任务时关闭；
- confirmation-only 窗口关闭；
- 连续快速启动/关闭 20 次；
- ControlPipe 丢失和 renderer lost 的 fail-closed 关闭；
- Release 关闭路径。
