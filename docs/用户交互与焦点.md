# 用户交互、焦点与输入状态

更新日期：2026-11-13

本文记录 Ui 进程的现行交互边界、已经搭好的状态机骨架和仍未完成的行为。
页面和焦点是瞬时 UI 状态，不属于 Shell 或 Protocol。

## 1. 事务边界

```text
页面 / 焦点 / 输入设备 / 覆盖层 / 全屏视觉状态
  -> MCast.Ui 本地

语言、主题、持久设置 JSON
  -> UiSettingsModel -> ControlPipe -> MCast.Shell

播放、暂停、Seek、音量、断开
  -> PlaybackController -> PlaybackBridge -> MCast.Protocol
```

Context menu、快捷键和焦点恢复只能调用既有的 Ui 门面，不能绕过
`PlaybackController` 直接操作 mpv，也不能自行写设置 JSON。

## 2. 交互状态机

`mcast::ui_process::UiInteractionState` 注册为 QML 单例 `Interaction`。当前状态为：

```text
Route
  Cast
  Settings

FocusRegion
  Media
  TopBar
  Settings
  Overlay

InputMode
  Mouse
  Keyboard
  Touch

Overlay
  None
  Info
  MediaMenu

fullscreen
```

约束：

- Settings 只能在非全屏进入。
- 全屏只允许 Cast route，焦点回到 Media。
- 全屏不允许 TopBar 取得焦点。
- 同一时刻只有一个 overlay。
- 打开 overlay 时记录之前的 FocusRegion，关闭后恢复。
- 输入模式只是输入事实，不改变媒体命令的权威边界。

`MainWindow.page` 和 `infoOpen` 已改为由 `Interaction` 推导，不再各自保存第二份页面
和 Info 状态。

## 3. 焦点范围

当前已经建立：

- `CastPage` 是 FocusScope，媒体入口是 Cast route 下唯一的页面级 Tab 入口。
- `SettingsPage` 是 FocusScope；进入设置页后媒体页面不再取得活动焦点。
- `InfoFlyout` 是 FocusScope，Tab/Shift+Tab 被限制在覆盖层内，Esc 关闭。
- 媒体控制栏中的按钮、进度条和自绘音量控件已退出 Tab 链；键盘通过媒体菜单操作。
- 顶栏自己的返回、断开、信息、设置按钮仍可 Tab。
- 最小化、最大化/还原、关闭三键设置成 `Qt.NoFocus`，不再进入 Tab 链。

全屏时，媒体 FocusScope 消费 Tab 和 Shift+Tab，焦点不能进入已经隐藏的标题栏。

## 4. 媒体菜单

`MediaContextMenu` 是媒体控制栏的键盘投影，当前包含：

- 上一个 / 播放暂停 / 下一个
- 后退 10 秒 / 前进 10 秒
- 音量增加 / 减少 / 静音
- 字幕占位项
- 显示效果
- 全屏

打开方式：

- 播放区域鼠标右键
- 媒体焦点下按菜单键
- 媒体焦点下按 Shift+F10

菜单关闭后恢复进入菜单前的焦点区域。菜单项仍通过 `Playback` 门面执行播放命令。

字幕项目前只是骨架占位，不能把它当作字幕选择功能已经完成。

## 5. 鼠标与触摸

当前只完成输入模式识别：

- 顶栏或媒体区域悬停记录 Mouse。
- 媒体区域按下时根据 Qt 合成事件来源区分 Mouse/Touch。
- 键盘按键记录 Keyboard。

触摸行为尚未切换。后续确定的规则是：

- 播放区域检测到触摸后进入 Touch 模式。
- 单击媒体区域切换控制栏显隐。
- 双击媒体区域播放/暂停。
- 必须处理双击第一下与单击之间的仲裁，不能让双击顺带切换控制栏。
- 设置页、按钮和滚动区域继续使用标准指针/触摸行为，不另做一套。

## 7. 全屏

全屏由 `platform/windows/FullscreenWindowController` 提供上层门面，
`Win32FullscreenWindow` 独占全部 Win32/DWM/原生消息逻辑。实现直接调整当前窗口，
不销毁或重建 `QQuickWindow`。QML 场景图、`MpvCore` 和 mpv render context
在切换期间保持存活。

```text
进入：
  保存 WINDOWPLACEMENT
  -> 最大化时先 SW_RESTORE
  -> 临时隐藏可见的 owned 子窗口
  -> 选择当前窗口所在显示器
  -> SetWindowPos 到 rcMonitor 宽度、顶部和右侧对齐，底部外扩 1 像素
     + WS_EX_TOPMOST
  -> 关闭 Win11 圆角和 DWM 边框/阴影

退出：
  -> SetWindowPlacement 恢复原位置/大小/最大化状态
  -> 取消 topmost
  -> 走与首次启动相同的普通窗口外观入口
     （样式位 -> 非客户区重算 -> DWM 边框、阴影、圆角）
  -> 恢复进入前可见的 owned 子窗口
```

QML 不再保存窗口几何，不使用 `fixSize()` 二次锁尺寸，也不使用
`Qt.callLater()` 重复摆位置。QML 只根据平台层返回的成功结果切换标题栏和焦点状态。

普通窗口外观只有一个平台层入口。DWM 阴影必须在
`SetWindowPlacement` 和 `SWP_FRAMECHANGED` 之后恢复，否则非客户区重算会把刚
挂回的阴影再次冲掉。

全屏矩形不能恰好等于 `rcMonitor`。DWM 会把这种窗口判为 fullscreen 并关闭
`DWMWA_NCRENDERING_ENABLED`；退回普通矩形后该状态不会自动恢复，窗口就永久
失去系统边框和阴影。全屏窗口只向屏幕下方 overscan 1 像素：顶部、左右两侧和
媒体区域保持原坐标，视觉上仍是满屏，但 DWM 全程按普通窗口处理。这 1 像素通过
`WM_NCCALCSIZE` 保留为非客户区，媒体客户区仍然是严格的 `rcMonitor` 尺寸。
另外，Qt 即使看不到原生边框，仍会按 frame margin 计算 QQuickWindow 的
渲染表面。进入全屏后会把 `QWindow` 强制同步到屏幕逻辑几何，再把 Qt 算出的
原生宽度固定回屏幕左上角；多出的部分留在屏幕外，不进入媒体客户区。

全屏期间移除原生窗口的标题栏、可缩放、最小化和最大化样式位，但保留
`WS_SYSMENU`。`WM_NCHITTEST` 固定在客户区，`WM_SYSCOMMAND` 拦截移动、缩放、
最小化、最大化和还原，`WM_WINDOWPOSCHANGING` 强制保持当前全屏位置与尺寸。
Alt+F4、任务栏关闭和系统菜单的关闭项仍然可用；系统菜单不能移动、缩放、最大化
或还原。全屏期间这些菜单项会直接从系统菜单删除，`WM_INITMENU` 还会再次置灰
作为兜底；退出全屏时系统菜单重置为默认项。

`Win+数字键` 属于 Windows Shell 的任务栏应用切换，单个窗口无法可靠拦截；
窗口能控制的是自身的移动、缩放、贴靠和最大化能力。

已手工验证：

- 普通窗口进入和退出全屏；
- 连续五次进入/退出后画面正常；
- 最大化窗口进入全屏后仍恢复为最大化；
- 显示效果子窗口存在时，全屏期间隐藏、退出后恢复；
- 全屏期间标题栏和窗口三键不进入辅助功能树，媒体入口保持可用。

仍需补充的回归覆盖是播放中的视频、混合 DPI 多显示器和任务栏位置变化。

## 8. 动画

`FluTheme.animationEnabled` 只覆盖部分 FluentUI 动画，媒体栏等自有 QML 仍有写死
时长。后续统一动画时必须：

- 使用一套 Ui MotionPolicy 管理时长和 easing。
- 页面进入/退出与按钮反馈共享总开关。
- 关闭动画时所有过渡立即落到终态。
- 焦点逻辑先完成，视觉动画只负责表现。
- 若动画开关持久化，仍通过 Shell 的设置链保存。

## 9. 后续快捷键页

快捷键设置页不直接绑 QML `Keys` 到具体动作，而应经过语义动作层：

```text
按键组合 -> MediaAction -> PlaybackController
```

这样以后增加冲突检测、恢复默认和持久化时，不需要重写媒体焦点入口。
