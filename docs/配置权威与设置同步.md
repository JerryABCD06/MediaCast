# 配置权威与设置同步

最后更新：2026-11-11

本文固定三进程架构中的用户设置所有权、JSON 文件边界和启动/更新时序。

## 1. 唯一权威

`MCast.Shell.exe` 是用户设置和持久配置的唯一权威。

- `MCast.Ui.exe` 不打开设置 JSON，不创建 `AppSettings`，不直接保存设置。
- UI 只持有 Shell 下发的内存快照，负责显示和提交修改意图。
- Protocol 只接收已经过 Shell 校验的接收/广播运行参数。
- 旧单体 `MCast.exe` 的回退路径仍可使用 `AppSettings`，但新 Ui 路径不再依赖它。

产品配置文件：

```text
MCast.Shell.exe 同目录/MediaCast.json
```

旧版接收状态：

```text
MCast.Shell.exe 同目录/MediaCast.Shell.json
```

Shell 首次加载时只读迁移旧状态文件中的接收开关，并在主 JSON 写入迁移标记；
迁移后不再把旧状态文件作为运行权威。新 Ui 不读写这两个文件。

测试模式的配置路径按实例隔离：

```text
MediaCast.<instance>.json
MediaCast.<instance>.Shell.json
```

## 2. JSON 结构

```json
{
  "ui": {
    "language": "System",
    "darkmode": "System",
    "accentmode": "System",
    "mica": true
  },
  "cast": {
    "newcast": true,
    "broadcast": true,
    "broadcast_interval": 10000
  },
  "device": {
    "name": "LAPTOP-NAME",
    "udn": "uuid:00000000-0000-4000-8000-000000000000"
  },
  "picture": {
    "brightness": 0
  }
}
```

规则：

- 未知字段原样保留，避免破坏用户手写配置或旧版本字段。
- Shell 只修改自己认识的字段；类型和范围错误拒绝保存。
- `ui.darkmode` 只接受 `System` / `Light` / `Dark`；
  `ui.accentmode` 只接受 `System` / `WindowsBlue`；语言代码使用安全字符集。
- `picture.*` 必须是 `-1000..1000` 范围内的整数；小数、越界值和非数字条目
  在读取时清理，在 patch 中直接拒绝。
- patch 里的 `ui` / `cast` / `picture` 只要出现就必须是对象，不能用错误类型
  静默跳过。
- 主 JSON 使用临时文件 + `MoveFileExW(MOVEFILE_REPLACE_EXISTING)` 原子替换。
- 坏 JSON 或读取失败都不覆盖原文件；本次使用内存默认值并禁止写回主配置。
- 设备 UDN 首次生成时优先迁移旧 `%LOCALAPPDATA%\MCast\renderer.ini` 的 UUID，
  再从 Shell 同目录的 `renderer.ini` 查找旧实现的备用位置；没有旧值时生成
  标准 UUID，不随实例名或启动次数变化。

## 3. UI 启动快照

ControlPipe 的顺序固定为：

```text
Ui Hello
Shell HelloAck
Shell SettingsSnapshot
Shell PeerIdentityGrant
PlaybackPipe 连接
MainWindow 创建
```

UI 在构造 `UiState`、`UiSettingsModel` 和 QML 引擎前就拿到设置快照，因此：

- 语言、明暗和强调色不会先按默认值创建一帧再切换；
- MainWindow 与确认窗口使用同一份设置；
- 设备名和 UDN 来自 Shell，不再由 Ui 读 `renderer.ini`；
- 设置快照缺失或无效时 Ui 启动失败，而不是自行读取磁盘形成第二权威。

## 4. 修改链路

```text
QML 用户操作
  -> UiState / UiSettingsModel 立即更新显示
  -> 合并为 JSON patch（250 ms 窗口）
  -> ControlPipe UiUpdateSettings
   -> Shell 在同一临界区校验版本、类型和范围
   -> Shell 候选副本原子写盘，成功后提交内存
  -> Shell 应用运行态
  -> ControlPipe SettingsUpdateResult
  -> ControlPipe SettingsSnapshot 回传
```

每条 `SettingsSnapshot` 带单调 `stateVersion`。Ui 忽略更低版本；更高版本
正常应用；相同版本允许重放，以便拒绝或保存失败后恢复权威值。Ui patch 携带
它所基于的版本。Ui 允许先乐观显示修改，但 Shell 拒绝后必须恢复上一份权威
快照。旧版本快照连 `UiState` 和设备信息也不会再应用。

Shell 应用范围：

- `ui.language`：托盘语言。
- `ui.darkmode`：启动屏幕和后续 Ui 的实际深浅。
- `ui.accentmode` / `ui.mica`：随快照进入 Ui。
- `cast.newcast`：发送 `SetReceivingEnabled` 给 Protocol。
- `cast.broadcast` / `cast.broadcast_interval`：发送 `SetDlnaBroadcast`
  给 Protocol，动态更新现有 SSDP 服务。
- `picture.*`：Ui 在 mpv 启动后回放；播放器值变化时再提交给 Shell。
- `device.name` / `device.udn`：启动 Protocol 时作为网络身份。

Patch 示例：

```json
{
  "ui": { "mica": false },
  "cast": { "broadcast": false, "broadcast_interval": 30000 },
  "picture": { "brightness": 25 }
}
```

## 5. PlaybackPipe 与设置

PlaybackSnapshot 仍然是播放事实权威，不并入设置快照：

- 播放器实际音量、静音、进度和当前画面参数由 Ui 报给 Protocol。
- `picture.*` 文件值只是启动时的恢复值；启动后播放器是运行态权威。
- 播放器报告值变化时，Ui 把对应 `picture.<name>` patch 交给 Shell 持久化。

设置快照不会携带高频播放遥测，避免每帧或每次音量变化都经过 Shell。

## 6. 故障原则

- JSON patch 校验失败：Shell 拒绝，不写入文件并记录日志。
- patch 先在 detached 候选对象上整体校验，任一字段失败都不会污染当前内存。
- JSON 保存失败：Shell 回滚本次内存修改，不增加设置版本、不广播成功快照，
  并保留可恢复的原文件。
- Shell 拒绝 patch 后仍回发当前权威快照；Ui 用该快照恢复语言、主题、强调色、
  Mica 和播放器画面参数。画面回滚先全部复位到中性值，再套用权威值，并抑制
  回滚过程产生的设置回写。发送失败只回滚已提交 patch，较新的未发送编辑保留。
- Protocol 暂不可用：设置仍由 Shell 持久化；Protocol 下次启动读取初始值。
  本次更新结果明确区分 `Applied`、`Rejected`、
  `SavedRuntimeFailed` 三种状态，不会把“已保存、运行态未应用”伪装成拒绝。
- Ui 退出或重启：Shell 保持设置不变，新 Ui 在首帧前重新取完整快照。
- Shell 退出：Ui 退出，不在本地补写任何设置。
