# 构建、测试与发布

更新日期：2026-11-12

## 1. 开发环境

当前 Windows 验证环境：

- CMake 3.21+
- Ninja
- Visual Studio 2022 或更新版本的 MSVC 工具链
- Qt 6.11.2 MSVC 2022 64-bit
- 默认 libmpv 开发包：`../../runtime/mpv-dev`
- 规范验证构建目录：`out/build/x64-Debug`

`MPV_DEV_DIR` 可在配置时覆盖，但默认值已经写入 `CMakeLists.txt`。

## 2. 配置与构建

在已加载 MSVC 环境的 PowerShell 中：

```powershell
cmake -S . -B out\build\x64-Debug -G Ninja `
    -DCMAKE_BUILD_TYPE=Debug `
    -DCMAKE_PREFIX_PATH=D:\Apps\Qt\6.11.2\msvc2022_64 `
    -DBUILD_TESTING=ON

cmake --build out\build\x64-Debug --parallel 8
```

修改过头文件、目标结构或第三方源码布局后，使用 clean-first 或新建构建目录：

```powershell
cmake --build out\build\x64-Debug --clean-first --parallel 8
```

原因不是一般意义上的“稳妥”：这个工程出现过 struct layout 不一致后链接成功、
运行即崩。日志必须与生成它的 EXE/PDB/MAP 配套。

## 3. 测试

```powershell
ctest --test-dir out\build\x64-Debug --output-on-failure
```

列出当前注册项但不运行：

```powershell
ctest --test-dir out\build\x64-Debug -N
```

2026-11-12 当前配置注册 **40 项**。其中覆盖 IPC、配置、语言、DLNA core/net/
session/Claim/HTTP/GENA、播放命令合并、媒体规划、图片序列、真实三进程影子和
Shell 单实例/交接。注册数量不等于通过数量；引用结果时必须写日期、构建目录和
是否 clean build。

本次文档归档只运行了只读的 `ctest -N`，没有重新执行全量测试。

## 4. 运行

构建目录不会把 Qt DLL 自动复制到 exe 旁边。开发机需要先把 Qt `bin` 和插件路径
放进环境：

```powershell
$env:Path = 'D:\Apps\Qt\6.11.2\msvc2022_64\bin;' + $env:Path
$env:QT_PLUGIN_PATH = 'D:\Apps\Qt\6.11.2\msvc2022_64\plugins'
.\MCast.Shell.exe
```

后台驻留：

```powershell
.\MCast.Shell.exe --background
```

`--background` 仍启动 Protocol 和托盘；它只跳过主窗口，不能理解成不接收网络。

## 5. 日志

- `MCast.Protocol.log`：网络、DLNA、GENA、Claim、媒体规划。
- `MCast.Ui.log`：QML、libmpv、播放桥、元数据和 SMTC。

测试实例可能生成带实例名的日志。不要用其他实例的日志证明当前实例状态。

## 6. 发布内容

最小文件边界见 [发布内容.md](发布内容.md)。发布时还必须处理：

- Qt 6 DLL 与 QML 插件；
- `libmpv-2.dll`；
- `qml/FluentUI/`；
- `config/metadata-pipeline.json`；
- 完整 `lang/<code>/`；
- `legal/` 和 `licenses/`；
- 三个 EXE 的图标、版本资源、任务管理器显示名称和可执行文件哈希。

当前没有正式的：

- `install()` 规则；
- CPack/安装器；
- `windeployqt` 自动调用；
- QML import 依赖扫描；
- 版本化 release manifest；
- 从干净源码生成发布目录的自动测试。

因此现阶段只能称为“开发构建”，不能称为正式发布包。

## 7. 发布闸门

正式发布前至少满足：

1. 源码 commit、工作树状态和构建产物一一对应；
2. clean build 成功；
3. 全量 CTest 有日期和日志；
4. 真实手机完成首次投送、换片、暂停、Seek、音量、主动断开和关闭窗口复开；
5. 从干净目录启动，不依赖开发机 PATH；
6. 隐私说明中的日志、配置和临时目录与实际一致；
7. 法律页与 `licenses/THIRD-PARTY-NOTICES.md` 一致。
