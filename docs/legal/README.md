# docs/legal —— 法律与合规文本

这里放的是**面向使用者**的说明。面向贡献者和公众的那几份，已经挪到仓库根目录了。

## 该去哪儿看什么

**仓库根目录**（平台会识别，面向所有访客）：

| 文件 | 内容 |
|---|---|
| `LICENSE` | 项目许可（GPL-3.0-or-later 全文） |
| `NOTICE.md` | 版权与许可声明、第三方组件概览、文档索引 |
| `CONTRIBUTING.md` | 贡献政策：inbound = outbound，**不签 CLA、不做版权转让** |
| `SECURITY.md` | 安全问题怎么报（含联系邮箱） |
| `licenses/` | **随包分发**的第三方许可全文 + 组件清单 |

**本目录**（面向使用者，也是将来"做进软件里"要用的素材）：

| 文件 | 讲什么 |
|---|---|
| `PRIVACY.md` | 隐私：不联网、不上报、留下哪些本地文件、监听哪些端口、可被发现意味着什么 |
| `LEGAL-NOTICES.md` | 总声明：免责、协议兼容 ≠ 认证、网络行为、用户内容、专利与商标的边界 |
| `TRADEMARKS.md` | 商标：与 DLNA / AirPlay / Google Cast / Miracast 等只是"兼容"关系 |
| `CODECS.md` | 编解码器与专利：**明确免版税**的一类、**有专利池**的一类，以及"义务落在分发方" |
| `README-LEGAL-SHORT.md` | 上面几份的一页摘要 |

**内部维护用**（不面向用户，也不进发布包）：

| 文件 | 讲什么 |
|---|---|
| `CHECKLIST.md` | 发布前过一遍的检查表 |
| `RELEASE-NOTICES.md` | 每个版本要记的变更（协议 / 隐私 / 编解码 / 许可 / 商标 / 安全） |
| `SUPPORT.md`、`CODE_OF_CONDUCT.md` | 当初模板里带的，个人项目暂时用不上；留着不碍事，不想要随时删 |

## 一条规矩

**"写实"优先于"写全"。** 这些文件里凡是描述本程序行为的句子，都必须和代码一致 ——
比如写了监听 8200/1900，改端口就得同时改这里。模板腔（"可能会""将来的版本应当"）
能删就删：读者要的是"这软件到底干什么"，不是"作者打算干什么"。

描述行为时，**宁可具体到端口号、文件名、开关位置**，也别用"某些情况下""相关组件"
这种话。
