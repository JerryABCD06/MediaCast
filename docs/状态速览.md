## 这是什么

Windows 上的 DLNA MediaRenderer：手机（vivo 相册 / BubbleUPnP 等）投屏过来，
电脑这边放。播放器是 libmpv，画面用 render API 合进 QML 场景。
界面只有一套：QML + FluentUI（`ui/MainWindow.*` + `ui/qml/**`）。
**普通启动会显示主界面，`--background` 启动只驻留托盘**；手机投送自动拉起
主界面时也与托盘打开走同一条加载路径。（旧的 Qt Widgets 界面 2026-09-14 退场了。）

## 现在能干什么

手机 DLNA 投屏 + 播放（图片 / 音乐 / 视频）、托盘常驻、勿扰模式、
Windows 媒体面板、主窗口（画面区、顶栏、设置页、媒体控制栏、悬停提示、全屏）、
原生启动屏幕、语言可切换（主窗口 + 托盘 + 媒体面板一起变）。新的 Shell
入口还具备 Qt-free DLNA Protocol、按需 MainWindow、PlaybackUiReady 门控、
接收开关和可强制控制点重新发现的主动断开。

## 分层

```text
MCast.Shell.exe（Win32：托盘、启动屏幕、配置、进程监督）
    ├── MCast.Protocol.exe（无 Qt：HTTP / SOAP / SSDP / GENA / DLNA 会话）
    └── MCast.Ui.exe（Qt/QML/libmpv，只在 MainWindow 需要时存在）

ControlPipe   身份、Ui 启动、确认窗口、接收状态
PlaybackPipe  播放命令、快照、PlaybackUiReady、断开请求
```

播放核心仍是：

```text
PlaybackController（core/）
    ↓
MediaPlayer / MpvCore
          └── MpvQmlItem（render API）
```

## 状态只有一份（界面照着读，别自己拼）

界面上会问的"局面"其实就两条，都算在 `PlaybackController` 里：

| 问什么 | 读哪个 | 谁在算 |
|---|---|---|
| 手机连着没有 | `Playback.peerConnected` | 协议层喂（有 GENA 订阅、且不是我们主动挂断） |
| 在投送视频 / 音乐 / 图片，还是没在投 | `Playback.castState` | `peerConnected` × 内容类型 × `idle`，就那十来行 |

消费方：顶栏状态胶囊（文字 + 颜色）、投屏页的引导语标题 —— 读 `castState`；
顶栏「断开连接」按钮的显隐、关窗确认框 —— 读 `peerConnected`。
**"手机连着没有"这一件事，代码里从头到尾只有一种写法。**
（`2026-09-14` 逐个查过：原先那两处分别写的是 `castState !== NoViewer` 和
`hasMedia`，都对、但都是绕着的说法，已经统一成 `peerConnected`。）

更细的那几个量（`showsPicture` / `mediaIsVideo` / `paused` / `hasMedia` / `idle`）
是**别的问题**用的（屏幕上有没有画面、控制栏该用哪套颜色、点一下有没有意义），
各自在头文件的注释里写明了为什么不能用上面那两条替代 —— 别混。

## 会咬人的约束

1. **改过任何 `.h`，必须删掉整个构建目录重配重编**。增量构建会漏依赖，
   结果是编译链接全过、一跑就崩。
2. PowerShell 长命令会被策略拦；`Remove-Item` 被挡。**写 `.ps1` 再跑**，删文件用
   `[System.IO.File]::Delete` / `[System.IO.Directory]::Delete`。
3. 提交信息**写进 `work\commitmsg.txt` 再 `git commit -F`**（长 `-m` 会被编码搞坏）。
4. **QML 里切页不能把 `MpvQmlItem` 藏起来**（render API 靠每帧渲染推进）；
   要"藏"就缩成 1×1。
5. 开关、滑块**别用 `checked: X.y` / `value: X.z` 绑属性**，一点就断。
6. 新加的 QML 文件要同时写进 `res/QmlUi.qrc`，改完要确认 rcc 真的重编了。
7. **启动屏幕不能用 QML，也不能放主线程。** 它必须在 `QApplication` 之前
   创建；D2D/DirectComposition 的初始化和动画在独立原生线程里跑。默认尺寸
   560×300 DIP、LOGO 96 DIP、进度条 280×4 DIP。主界面首帧到了才退场，
   最短展示 280 ms，淡出 150 ms。背景**不用 Mica**，由 DWM 画普通窗口背景。
   动画节拍不能再用 `SetTimer(16)`：它会被系统计时精度量化，和
   `Present(1,0)` 叠起来容易掉到 30 FPS。现在启动屏幕可见时直接跑独立的
   “处理消息 → 绘制 → `Present(1,0)`”循环，让 DXGI 的垂直同步自己定节拍；
   交换链用 3 个 buffer，隐藏后立即回到阻塞消息循环。

## 启动方式

| 启动方式 | 行为 |
|---|---|
| 普通双击 `MCast.Shell.exe` / 无参数启动 | 显示原生启动屏幕 → 主界面 |
| `MCast.Shell.exe --background` | 完全不显示启动屏幕和主界面，只驻留托盘 |
| 托盘打开、手机投送自动拉起 | 如果主界面尚未建好，先显示同一个启动屏幕 |

旧的 `MCast.exe` 仍保留为生产回退入口；正式切换完成后才会删除。

启动屏幕是 topmost 活动窗口，加载期间挡住下面的半成品主界面；首帧后才把焦点
交还主界面。DPI Awareness 在创建启动屏幕前就钉成 Per-Monitor V2，否则 Qt
初始化后会让已经显示的窗口突然跳尺寸。

浅/深只认 `UiState.dark`：先确定实际主题再把启动屏幕显出来，运行中主题变了
也通过 `darkChanged` 同步。DWM 的深色属性、进度条轨道色和强调色都跟同一个
布尔值走，不自己再读一遍系统主题。浅/深强调色分别是 FluentUI 的
`#0067C0` / `#4CC2FF`，轨道色是 `#D6D6D6` / `#636363`。

“跟随系统”有一个专门的启动竞态保护：主线程把 `followSystem` 一起传给启动
屏幕；后者在每次真正显示前、以及收到 `WM_SETTINGCHANGE` 时重新读一次系统
主题。这样即使 Qt 还没开始跑事件循环，也不会拿启动时的旧值画第一帧。
强制浅/深模式则完全忽略 `WM_SETTINGCHANGE`，不会被系统设置覆盖。

## 界面上的几个时间常数

| 值 | 用在哪 |
|---|---|

| 3 s | 暂停 / 图片时鼠标停手后收起 |

## 配色的两条硬规矩

- **主题色实心圆底上的字形：深色那套用黑、浅色那套用白。** 库里自己的
  `FluFilledButton.qml` 就是这么定的（`textColor: FluTheme.dark ? 黑 : 白`），
  WinUI 的 `TextOnAccentFillColorPrimary` 同理。理由是**对比度**：深色那套的蓝
  是"提亮"过的（`accentColor.lighter`，和库里 `FluTheme.primaryColor` 同一档，
  实测 `#4CC2FF`），白字压上去不足 3:1、黑字 7:1 以上。媒体栏那个播放/暂停键
  原来写死白的，2026-09-14 改成跟着这条走。
- **控制栏自己那套明暗（`darkStyle` = 压着画面 或 程序深色主题）不能拿
  `FluTheme.dark` 顶替。** 两者在"浅色主题 + 放视频"的时候会分岔 —— 栏是深色
  的，`FluTheme.dark` 却是假。凡是画在栏上的颜色（主题蓝、悬停底色、图标灰、
  字形）都得照栏自己的判据来，见 `MediaBar.qml` 里那几个 `property color`。
- **系统主题色必须用 Windows 官方七级色阶。** 设置里的 `ui.accentmode` 只有
  `WindowsBlue` / `System` 两个值，新配置默认 `System`。后者通过
  `UISettings.GetColorValue` 读取
  `Accent`、`Light1..3`、`Dark1..3`，不自己按 RGB 手算。WinUI 的规则是：
  浅色强调填充用 `SystemAccentColorDark1`，深色强调填充用
  `SystemAccentColorLight2`；FluentUI 正好分别对应 `accentColor.dark` 和
  `accentColor.lighter`。启动屏幕也接收这两个最终颜色。

## 全屏：一条不能碰的线

**不许用 Qt 的 FullScreen 状态、不许改窗口 flags、不许"藏一下再显示"。**

这台机器上（AMD Radeon 780M + Qt 6.11 + **OpenGL 后端**）窗口表面只要过一遍
"状态/大小大改"，Qt 就再也不往屏幕送帧了 —— 场景照常在画，屏幕和 DWM 收到的
却是纯黑。用一个跟本工程无关的 `qml.exe` 也能复现（`QSG_RHI_BACKEND=opengl`），
换 D3D11 就正常；而本工程必须用 OpenGL（mpv 的 render API 只有它）。详见
`待办.md` 里那一条。

现在的做法：**全屏 = 自己把窗口摆满 + `QWindow::destroy()`/`show()` 让原生窗口
重来一遍**（新建的窗口从来不黑），置顶和圆角走 `WindowFrame` 的 Win32 调用。

## 要加子窗口：用 `createChildWindow`

子窗口（依附主窗口、不占任务栏、主窗口最小化它跟着藏、主窗口销毁它跟着走）统一走
`MainWindow.qml` 里那个 `createChildWindow(component)` —— **别自己
`createObject`**：全屏切换会把主窗口的原生窗口拆掉重建，那一下系统会把从属窗口
一起带走。登记之后 C++ 那边（`Shell.adoptChildWindow` + 全屏那段）统一照看它。
细节和踩过的坑在 `待办.md` 的"加子窗口"那一节。
