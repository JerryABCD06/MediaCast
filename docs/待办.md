**问题**：媒体控制栏的字幕按钮仍是空壳；现有播放核心已能取得字幕轨道和歌词数据，

**验收**：

### 5. 远程封面统一护栏

**问题**：协议 `albumArtURI` 目前由 QML/SMTC 消费，缺少统一的下载超时、最大

**验收**：只在一个平台无关层下载和校验；QML 与 SMTC 消费同一份本地缓存；
超大、伪造、超时和解码失败都安全回退；失败不阻塞播放。

**验收**：补充数据驱动规则；截图文件名保留，日期、纯数字、随机 token 和已知
控制点噪声仍被过滤；规则测试覆盖标题、副标题和音频字段。

### 7. 歌词展示

**验收**：先确定字幕与歌词是否共用 UI；不支持的格式有清晰状态；时间解析失败时

## P1：架构与边界

### 8. 进程故障恢复落到生产链

**问题**：`RestartController` 未接入；Protocol 崩溃不会自动重启，Shell 崩溃会
经 Job 杀死 A/B，没有反向拉起。

**验收**：Protocol 异常退出有预算、退避和稳定运行清零；Shell 退出时 A/B 合理
退出；反向拉起只保留一个真正执行者；日志能区分“网络面重建”和“进程重启”。

### 9. confirmation-only 自动冷启动

**问题**：`MCast.Ui.exe --confirmation-only` 可手工运行，但 Shell 没有按需选择它。
没有 UI Control 连接时，确认请求当前直接拒绝。

**验收**：主窗口不存在时，Shell 能启动唯一 UI 进程显示确认窗口；窗口就绪、
失败、超时和控制连接断开都有独立信号；不能复用主窗口首帧看门狗。

### 10. 仲裁策略持久化

**问题**：DLNA Runtime 当前硬编码“允许抢占 + 抢占前确认”；设置模型尚未持久化
这些策略，`cast.newcast` 只是接收开关，不是抢占开关。

**验收**：Shell 拥有策略权威；UI 设置、托盘、Protocol 运行态和重启恢复一致；
修改策略只影响之后的 Claim，不改变已有 deadline。

### 11. DLNA HTTP owner 长等待

**问题**：部分 Play/Stop 路径仍在 HTTP owner 线程内最多等待 Playback IPC 5 秒。
这是高频控制点拥塞的剩余风险。

**验收**：提交播放命令后立即返回 Pending，由完成事件异步回填 SOAP；网络线程不再
承担媒体等待；快放、暂停、查询和断开并发时无队头阻塞。
