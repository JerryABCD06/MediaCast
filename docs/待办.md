## 现在到哪儿了

代码全在版本控制里。**具体的提交用 `git log --oneline` 看** —— 这份文件里
不抄提交号，抄了第二天就过时。

这一轮做完的几件事：mpv 播放核心拆出来、画面渲染进 QML、播放控制从协议层
抽成 `PlaybackController`、用户设置文件、有投屏时自动拉起新界面。

**能跑的**：手机通过 DLNA 投屏，电脑上播放；托盘常驻；勿扰模式；Windows
媒体面板；新界面（FluentUI）能打开、能切页、语言和深浅跟系统走；**画面已经
渲染在新界面里**（`kRenderVideoInNewUi = true`）。

**播放层的形状**：

```
MediaPlayer（抽象接口，协议层只认它 —— 从头到尾一个字没改）
    └── MpvCore               mpv 实例 + 事件线程 + 状态缓存 + 命令 + 画面调节
          ├── LibMpvPlayer    wid 外壳：画面画进原生窗口（旧界面用）
          └── MpvQmlItem      render API 外壳：画面由 QML 场景图合成（新界面用）
```

**协议层已经解耦**：`DlnaRenderer` 不直接碰播放器，中间隔了
`PlaybackController`（中性枚举 `State` / `PlayMode` / `LoadStatus`，队列三格，
看门狗）。DLNA 的字符串词汇只在 `SoapHandler` 里翻译。将来接别的协议时，
新协议只要说中性的话就行。

> 一个 mpv 实例**只能有一条画面输出路径**（`vo` 只能设一次，wid 和 render API
> 互斥）。所以 `kRenderVideoInNewUi` 这个开关是**过渡用的**：为 true 时旧界面
> 的画面区是空的；为 false 时新界面没有画面。定了走新界面之后，这个开关和
> 旧界面一起删。

### 别踩的坑

- **`FluWindow` 默认 `autoDestroy: true`，关窗口 = 把窗口对象整个销毁。**
  而 `NewUiWindow` 拿的是个裸指针（`m_window`），窗口一没指针就野了 ——
  下一次投屏进来调 `m_window->show()` 会崩在 Qt6Gui 内部读一个非法地址，
  栈上什么线索都没有（`Qt6Guid+0x34BA22`，连崩四次才查清）。
  `NewUiWindow.qml` 里已经设成 `autoDestroy: false`（关窗 = 藏起来），
  **别人改那个地方之前先看一眼这条**。
- **同一个进程里加载第二个 `QQmlApplicationEngine` 会崩**（实测崩在 Qt6Qml
  的 `m_engine->load()` 上）。所以别指望"窗口没了就重建一个"这条路 ——
  设计上要保证 QML 引擎一个进程只建一次。
- **脚本里的 exe 路径别写死构建目录名。** 清掉旧构建目录之后，那些
  `mcast-build2` / `mcast-build5` 之类的写死路径全烂了，症状是"程序起来了
  又立刻没"或者一串"目标计算机积极拒绝"。现在统一指向 `mcast-build11`。

> 顺带：那些脚本起了 MCast 之后**不会**自动挂 Qt 的 DLL 目录，不挂的话
> 进程会立刻退出。`mpvcore-regression.ps1` 里已经补了一行，别的脚本大多
> 本来就有。
